# Сайт клиента — правила для агента

Проект сделан по принципу spec coding. Главные документы — в `specs/`, код — производное от них.

## Перед любой работой
0. Прочитай `specs/STATUS.md` — где проект сейчас и что ждём. В конце сессии обнови его (этап, сделано, ждём от кого, следующий шаг).
1. Прочитай `specs/02-spec.md` (что строим), `specs/decisions.md` (решения проекта) и `specs/05-tasks.md` (что уже сделано и что дальше).
2. Требования, которые действуют всегда, — стандарт AI-Ready сайта: `~/Desktop/NikitOS/Resources/Frameworks/AI-Ready сайт — стандарт.md`. Spec может отступить от стандарта только через раздел «Исключения».
3. Правила вёрстки и текста — скилл `web-dev` NikitOS: shadcn/ui, Главред, Типограф.

## Как работать с задачами
- Бери задачи из `specs/05-tasks.md` по порядку, по одной. После задачи — проверка из её описания, отметка `[x]` и строка в «Журнал».
- Нашёл неточность или пробел в spec — не додумывай: поставь задаче `[?]`, запиши вопрос в «Вопросы» и переходи к следующей независимой задаче.
- Задача, которой нет в `05-tasks.md`, — сначала предложи правку spec и задач, потом делай.

## Git
- Источник правды — репозиторий на GitHub. Облачная сессия клонирует его, работает в ветке `claude/<задача>` и открывает PR; после зелёного `npm run check` PR сливается сам и выкладывается (`.github/workflows/pr.yml`), метка `needs-nik` — ждёт Ника. Push кода в `main` из облака не делаем, файлы через мост Cowork не гоняем (никаких tgz).
- Решение, которое меняет объём или инфраструктуру, правится в `specs/02-spec.md` / `04-plan.md` **тем же коммитом**, что и код.

## Контент
- Все факты о клиенте живут в `src/content/*.ts` и `content/blog/*.md`. Из них же генерируются страницы, JSON-LD (`src/lib/schema.ts`), `llms.txt` (`src/lib/llms.ts`) и `sitemap.xml`. Один факт — одно место.
- Факты (цены, сроки, цифры, отзывы, регалии, клиенты) берутся только из `specs/00-brief.md` и материалов клиента. Нет факта — `TODO(клиент): что нужно`. Никогда не выдумывай.
- Первый абзац каждой страницы — прямой ответ на её главный вопрос (поле `answer`).
- Ориентир вместо факта (рыночная цена, типовой срок) допустим только с комментарием `// estimate` рядом и строкой в «Вопросах» `05-tasks.md`: `npm run check` выводит все такие места.
- Фирменные формулировки (слоган, hero) из `specs/decisions.md` переносятся буквально; SEO-формулировка — в title и подзаголовок.
- Функцию убираем флагом в `site.features`, а не удалением кода.
- Новая страница = маршрут в `src/app` + JSON-LD + строка в `src/app/sitemap.ts` + ссылка в `src/lib/llms.ts`, если страница важна для нейросетей.

## Команды
```bash
npm install
npm run dev        # http://localhost:3010
npm run build      # статический сайт в out/ (перед сборкой сам запускается типограф)
npm run check      # сборка + все проверки: TODO, домен, geo-check ≥ 8/10, индексация, Метрика, ИНН/ОГРН, Главред, цвета, перенос
node scripts/glavred.mjs <файл>   # Главред по одному тексту
```

## Нельзя
- Подключать Google Fonts, внешние CDN и скрипты, которые блокируются в РФ.
- Прятать текст за JavaScript: весь контент — в HTML.
- Размечать в JSON-LD то, чего нет на странице (рейтинги, отзывы, цены).
- Деплоить с проваленным `npm run check`.
